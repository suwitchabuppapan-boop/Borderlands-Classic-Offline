# สยามอรุณ — ชุดสกิลและ Effect Part สำหรับประกอบ VFX

วันที่: 2026-10-20 · ฐานเกม: รุ่น 1.16 · สถานะ: แบบออกแบบสำหรับพัฒนา

ผู้เล่นอนุมัติชุดสกิล Class 1 ทั้ง 5 อาชีพและ Class 2 ทั้ง 10 อาชีพ แล้วให้ดำเนินการแตก Effect Part ต่อ เอกสารนี้เก็บรายการชิ้นส่วน สูตรประกอบ และข้อกำหนดภาพ ไม่ได้เพิ่มสกิลหรือรูปภาพใหม่เข้าเกม รุ่น 1.16 ยังมีสกิลใช้งานจริง 16 รายการ

## ขอบเขตและจำนวน

- ชุดออกแบบมี 60 สกิลประจำอาชีพ: 45 สกิลกดและ 15 สกิลติดตัว รวมปฐมพยาบาลเป็น 61 รายการ
- Class 1 มี 4 สกิล Class 2 เพิ่ม 4 และสืบทอด Class 1 ของสายตัวเองทั้งหมด ต่อหนึ่งตัวละคร Class 2 จึงมีสกิลกด 6 สกิล ติดตัว 2 สกิล และปฐมพยาบาล 1 สกิล
- `★` หมายถึงสกิลปัจจุบัน สกิลอื่นเป็นชื่อและกลไกที่อนุมัติเป็นแบบออกแบบสำหรับพัฒนา ค่า SP/คูลดาวน์/พลังของสกิลใหม่ต้องผ่านการกำหนดสมดุลก่อนเปิดใช้งาน
- คลังภาพมี 58 Part templates: ส่วนกลาง 8, Class 1 อาชีพละ 4 รวม 20, Class 2 อาชีพละ 3 รวม 30 จำนวนนี้คือแม่แบบชิ้นส่วน ไม่ใช่จำนวนไฟล์ภาพหรือจำนวนเฟรม
- Class 2 ใช้ชิ้นส่วนกลางและสายต้นทางร่วมกันได้ สีและรูปทรงเป็นเอกลักษณ์ภาพ ไม่กำหนดธาตุ ดาเมจ หรือจำนวนฮิต

## รูปแบบภาพและข้อมูลแต่ละ Part

ภาพเป็นแฟนตาซีคลาสสิกผสมสยาม ใช้รูปคมดาบ กลีบบัว อักขระ ผลึก ขนครุฑ และนาคา ที่วาดขึ้นใหม่ สีแกนแสงงาช้าง ขอบสีประจำสาย และละอองเบาบาง ชิ้นภาพแบบสไปรต์ใช้พื้นโปร่งใสและกริดเฟรมคงที่ ส่วนวิถี รอยคม วงรัศมี และการเชื่อมจุดใช้ Canvas เพื่อปรับตามทิศและระยะจริงได้

Part สั้นตั้งงบภาพ 6–8 เฟรม ส่วนสถานะวนตั้งงบ 4–6 เฟรม เป็นข้อกำหนดการผลิตภาพ ไม่ใช่อัตราฮิตหรือเวลาร่าย ขนาดต้นแบบ 32/64/96/128 พิกเซลตามพื้นที่ของชิ้นส่วน วงพื้นที่ย่อขยายตามรัศมี world ที่ระบบสกิลส่งมา

ข้อมูลต่อแม่แบบ: `id`, `shape/backend`, `anchor`, `layer`, `directionMode`, `palette`, `size`, `frameCount`, `envelope`, `endPolicy` สูตรสกิลระบุ `partId`, `eventGate`, `offset`, `rotation`, `scale`, `variant`, `stateBinding` เพิ่มเติม รูปทรงร่วมใช้ parameter/variant แทนการสร้างไฟล์ซ้ำ

## จุดยึด ทิศ และชั้นภาพ

| จุดยึด | พฤติกรรมและข้อมูลอ้างอิง |
|---|---|
| `weapon_tip` | ปลายอาวุธของภาพตัวละครประจำอาชีพ ต้องเพิ่ม metadata จากเฟรมจริงทั้ง 4 ทิศและเฟรมที่ใช้งาน ไม่ใช้ค่า hand offsets เก่ามาเดาตำแหน่ง และไม่แยกวาดแขนใหม่ |
| `body` | ลำตัวผู้ใช้ ใช้สำหรับรวมพลัง/เกราะ/บัฟ โดยหลบใบหน้า |
| `feet` | เท้าผู้ใช้ วงบนพื้นหมุนรอบเท้าจริง ไม่หมุนรอบลำตัวแล้วชดเชยแกน Y |
| `target_body` | ปะทะใช้ตำแหน่งโดนที่บันทึกในเหตุการณ์ ส่วนสถานะติดตัวเป้าติดตามเป้าที่มี UID และสถานะจริง |
| `ground_point` | จุด world ที่เลือกหรือบันทึกไว้ เช่น พื้นที่โจมตี/บ่วง ไม่วิ่งตามเป้าเมื่อเป้าเดินออก |

| ชั้นภาพ | ลำดับ |
|---|---|
| `ground` | วง/ตราบนพื้นก่อนวาดตัวละครและมอนสเตอร์ |
| `back` | แสงด้านหลังผู้ใช้ ก่อนวาดสไปรต์เจ้าของ ตามทิศและลำดับความลึก |
| `front` | รอยคม วิถี และปะทะด้านหน้า ตามตำแหน่งและทิศที่บันทึก |
| ชั้นอ่านผลร่วม | ชื่อ เลขดาเมจ Critical!!/Miss/Lucky!! วาดเหนือ VFX และคงระบบจัดตำแหน่งของ 1.16 |

แอนิเมชันชนิดพุ่งใช้เวกเตอร์ต้นทาง→ปลายทาง ชนิดอาวุธใช้ทิศที่บันทึกตอนปล่อยและ socket ของเฟรมนั้น ส่วนวงรอบตัวใช้เท้าเป็นจุดหมุน ชิ้นส่วนที่ถูกวาดซ้ำต้องไม่เปลี่ยน snapshot, RNG, ค่าสถานะ หรือเวลาเกม

## เวลา เหตุการณ์ และการจบภาพ

- เกมปัจจุบันคิดผลหลายสกิลทันที ภาพรวมพลัง/วิถีเป็นการแสดงเหตุการณ์ที่ยืนยันแล้ว การทำภาพร่ายล่วงหน้าหรือรอดาเมจจนลูกเวทถึงเป้าต้องออกแบบกลไกแยกต่างหาก
- อายุภาพเดิมคงไว้: attack .28 วินาที, skill .45 วินาที, impact .25 วินาที ภาพสลายอยู่ภายในอายุเจ้าของเหตุการณ์
- Part ปะทะเกิดเฉพาะ hit ที่เกิดจริง ราชวังทวิคมมีได้ถึง 3 ฮิต กระบวนครุฑามีได้ถึง 2 ฮิต และหยุดตามฮิตที่ระบบทำได้จริงเมื่อเป้าตายก่อน ส่วนรอยกรงเล็บสามเส้นยังเป็นหนึ่งการโจมตีตรง
- `status_applied`, `status_tick`, `status_end`, `shield_absorb`, `mark_consumed`, `cleanse_success`, `move_committed` เป็นชื่อสัญญาเหตุการณ์ที่เสนอสำหรับสกิลใหม่ ยังไม่มี API เหล่านี้ครบใน 1.16 ชิ้นภาพรอข้อมูลจริงจากระบบก่อนเปิดใช้
- บัฟ/DoT/ประจุ/บ่วงอ่าน remaining, count, target UID และผลสถานะจริง วนภาพจนสถานะหมด/ถูกใช้/ถูกล้าง/เจ้าของตายตามกติกา ไม่ใช้จำนวนเฟรมเป็นนาฬิกาเกม
- มณีเดิมเพิ่มจากโจมตีปกติที่โดน สูงสุด 3 เม็ด อยู่ได้ 12 วินาที ระเบิดเดิมใช้ได้ที่ 0–3 เม็ด ส่วนม่านมณีใหม่ต้องใช้ประจุหนึ่งเม็ดตามกลไกที่ออกแบบ
- บ่วงเดิมรอได้ 12 วินาที รัศมีตรวจจับ 34 โจมตีหนึ่งเป้าที่ทำงานและตรึง 3 วินาที แยกภาพบ่วงรอ ภาพทำงาน และภาพตรึง เป้าที่ต้านตรึงแสดงเฉพาะสถานะ/เครื่องหมายที่ระบบให้จริง
- พายุบัวแก้วรัศมี 90 และเขตอักขระศักดิ์สิทธิ์รัศมี 105 ให้ผลทันที ห่าศรมนตรารัศมี 85 ไม่เพิ่มฮิตตามจำนวนเส้นศร เขตอักขระเดิมไม่มีการฮีลซ้ำเป็นช่วง ๆ
- อักขระคุ้มกายเดิม 6 วินาที โล่สวนศึก/บัฟครุฑาเดิม 5 วินาที พิษเดิม 5 วินาที เลือดไหลเดิม 4 วินาที ส่วนสถานะใหม่ใช้ระยะเวลาจากกลไกใหม่ที่กำหนดจริง
- สกิลติดตัวด้านค่าสถานะไม่มีลูปแสงประจำตัว ใช้ผล VFX ของการกระทำตามปกติ ส่วน passive ที่ให้เครื่องหมายเงื่อนไขแสดงเฉพาะเมื่อมีสถานะนั้นจริง
- เมื่อเปลี่ยนแผนที่ ตาย รีเซ็ต หรือนำเข้าเซฟ ให้จบภาพ transient และผูกสถานะใหม่จากข้อมูลที่ถูกต้อง ภาพจากเวลาที่ชดเชยเบื้องหลังไม่ถูกคิวมาระเบิดพร้อมกันเมื่อกลับหน้าเกม

| `common.hit_spark` | ประกายคม 64px | target_body / front | hit กายภาพจริง ไม่เกินอายุ impact |

| `common.status_tick` | ประกายสถานะขนาดเล็ก 32px ปรับสีและรูปย่อย | body หรือ target_body / front | tick/ใช้สถานะที่ยืนยันแล้ว ไม่สร้าง tick ใหม่ |

## สายมนตราและสายอาคม: Part เฉพาะ 20 ชิ้น / สูตรสกิล 24 รายการ

สถานะเอกสาร: แบบผลิตภาพหลังผู้ใช้อนุมัติชุดสกิล 60 รายการ ยังไม่มีการเพิ่มสกิล กลไกหรือไฟล์ภาพในเกม ★ หมายถึงสกิลปัจจุบัน ส่วนสกิลอื่นเป็นแบบเสนอใหม่

Class 2 ใช้คลัง Part ของ Class 1 ต้นทางได้ครบ รูปแบบภาพใช้สไปรต์ RGBA พื้นโปร่งใสสำหรับลายเฉพาะ และใช้ Canvas ยืด หมุน จัดระยะ หรือวาดขอบเขตพื้นที่ให้ตรงกติกา สไปรต์สั้นวางงบ 6–8 เฟรมและลูปสถานะ 4–6 เฟรม; จำนวนเฟรมไม่ใช่จำนวนฮิตหรือช่วงคิดดาเมจ

คำอธิบายจุดยึด: `weapon_tip` คือจุดปลายอาวุธที่ต้องกำหนดใน metadata ของเฟรมตัวละครครบ 4 ทิศ; `body` และ `feet` ของสถานะติดตามผู้ใช้จริง; `target_body` ของปะทะใช้ snapshot ตอนโดน ส่วนตราที่คงอยู่ติดตาม UID ของเป้าที่มีสถานะ; `ground_point` ของพื้นที่หนึ่งครั้งใช้พิกัด snapshot ไม่เลื่อนตามเป้า

### ข้อผูกสำหรับการผลิตและการประกอบ

- Part ทั้ง 20 ชิ้นไม่รวมชิ้นร่วม 8 ชิ้นที่กำหนดในคลังกลาง และไม่มีการเพิ่มชิ้นร่วมซ้ำใน fragment นี้
- รูปทรงบัวใช้ม่วงอ่อน–งาช้าง มณีใช้หยก–ทอง อักขระใช้เขียวหม่น/ขาว–ทอง และครุฑใช้แดงชาด–ทอง สีเป็นภาษาภาพ ส่วนชนิดความเสียหายอ่านจากกลไกจริง
- Part ปะทะหนึ่งครั้งใช้ snapshot ตำแหน่งโดน; Part บัฟ/ประจุ/ตราติดตาม entity จริงเฉพาะเมื่อ state ยังทำงานอยู่ การตาย ย้ายแมป ล้างสถานะหรือหมดอายุหยุดลูปที่เกี่ยวข้อง
- โล่ดูดซับ ตราบัว โบนัสสกิลถัดไป การชิ่งเวท การชำระ และย่างครุฑาเป็นกลไกเสนอใหม่ ต้องมี state/event ที่เชื่อถือได้ก่อนเชื่อม Part สถานะ ไม่มีการจำลองผลเหล่านี้ด้วยอนิเมชันอย่างเดียว
- ภาพหนังสือ/สนับมือใช้ท่าตัวละครประจำอาชีพเดิมพร้อมจุดปล่อยตามเฟรม หลีกเลี่ยงวาดแขนเพิ่มหรือวางตราแสงทับใบหน้า
- สกิลติดตัวทั้ง 6 ชื่อในตารางไม่มีลูป VFX ระหว่างยืนหรือเดิน ค่าติดตัวที่เพิ่มความแรงไม่สร้าง hit แฝงหรือภาพปะทะเพิ่ม
- จัดแสงด้านข้างและช่องโปร่งให้เห็นตัวละคร เป้าหมาย และเลขดาเมจ โดยชั้นเลขดาเมจเป็นชั้นอ่านผลร่วมของเกม

- คลิปสั้นเตรียม 6–8 เฟรม ส่วนคลิปวน 4–6 เฟรม เป็นงบงานภาพเบื้องต้น อายุภาพอิง event หรือ remaining จริง ไม่ใช้จำนวนเฟรมเป็นตัวกำหนด hit, SP, cooldown หรือระยะบัฟ
- Part เฉพาะอาชีพทำเป็นภาพ RGBA พื้นโปร่งใส รูปร่างคมชัดและแสงพอดี การยืดริ้ว หมุนตามทิศ และวงพื้นที่ใช้ Canvas ช่วยประกอบได้ ตัว Passive ใช้ไอคอนในเมนูเป็นหลัก
- คริใช้ผล critical จริงผ่านชั้นร่วมของเกม; ไม่มีการให้สกิลติดคริ การรับประกันคริ หรือ Guard เพิ่มจากการเลือก Part
- กลไกสกิลใหม่ที่ยังไม่อยู่ในเกมต้องมี state/event ที่ engine รับรองก่อนเปิด Part ที่สื่อผลนั้น ตารางนี้ไม่ระบุค่าดาเมจ SP cooldown หรือเวลาบัฟใหม่แทนงานปรับสมดุล

สรุป fragment นี้: **6 อาชีพ, 20 Part เฉพาะ, 24 สูตรสกิล** โดยมีสกิลปัจจุบัน 6 รายการ และข้อเสนอใหม่ 18 รายการ รวม Passive 6 รายการที่ไม่สร้าง VFX คงอยู่ตลอดเวลา

## สายธนู: พรานป่า → พรานนาคา / ศรมนตรา

เอกสารออกแบบ Effect Part สำหรับชุดสกิลที่ผู้ใช้ตกลงแล้ว ข้อมูลส่วนนี้มี Part เฉพาะ 10 ชิ้น: พรานป่า 4 ชิ้น พรานนาคา 3 ชิ้น ศรมนตรา 3 ชิ้น สูตรสกิลมี 12 รายการ: สกิลปัจจุบัน 3 รายการและข้อเสนอใหม่ 9 รายการ (รวมติดตัว 3 รายการ) Class 2 สืบทอด Part และสกิลต้นทางครบ 4 รายการ

ใช้ Part ร่วมจากคลังกลางตาม ID ที่กำหนดไว้ โดยไม่มีการสร้างนิยามซ้ำในตารางนี้ สีของ Part เป็นภาษาภาพ ส่วนชนิดความเสียหายและสูตร DEX/INT เป็นหน้าที่ของระบบสกิล

### รูปแบบภาพและจุดยึด

- พรานป่า: เขียวใบไม้–ทองอ่อน–งาช้าง รูปทรงศร ขนนกและฝุ่นบาง
- พรานนาคา: หยกเข้ม–ทอง รูปขดนาคาและตราล่า สืบทอดตัวศรจากพรานป่า
- ศรมนตรา: ฟ้า–ม่วง–งาช้าง รูปศรอักขระ ตราเรขาคณิตและเศษแสง
- Part เป็นสไปรต์ RGBA พื้นโปร่งใสหรือภาพผสม Canvas สำหรับวง/วิถี ภาพสั้นเริ่มด้วย 6–8 เฟรม ภาพวน 4–6 เฟรม จำนวนเฟรมไม่กำหนดจำนวนฮิตหรือระยะสถานะ
- จุด `weapon_tip` อ้างจากท่าตัวละครและอาวุธประจำสายครบ 4 ทิศ; วิถีมุ่งจากจุดปล่อยไปยัง snapshot เป้าหมาย โดยไม่เปลี่ยนแขนหรืออาวุธในสไปรต์ตัวละคร
- `target_body` ของปะทะล็อกตำแหน่งตอนโดน; `target_body` ของสถานะติดตามเป้าที่มีสถานะจริง; `ground_point` ของบ่วงคงตำแหน่งวาง ไม่ไหลตามผู้เล่น

### ข้อผูกพันกับระบบปัจจุบันและกลไกใหม่

1. วงเริ่ม วิถี และภาพปะทะอาจเปิดในเฟรมเดียวกันตามผลโจมตีทันทีของระบบปัจจุบัน; สูตรภาพไม่เพิ่มเวลาร่ายหรือหน่วงดาเมจเพื่อรอให้ศรเดินทาง
2. ภาพสถานะหยุดตาม timer ของเกม รวมการหมดเวลา เปลี่ยนฉาก ตาย หรือล้างสถานะ ภาพวนไม่เป็นเจ้าของนาฬิกาอิสระ
3. ฝนศร เส้นศรคู่ แสงสะท้อนหรือ Part ซ้ำ เป็นจำนวนชิ้นภาพ ผลดาเมจ/SP/คูลดาวน์ยึดกลไกสกิลเท่านั้น
4. เลขดาเมจ Critical!! / Miss / Lucky!! อยู่ชั้นข้อความกลาง ไม่มี Part เฉพาะสายยิงข้อความหรือสร้างผลคริแทนระบบ
5. สกิลใหม่ทั้งการถอย สองฮิต ทะลุ เครื่องหมายล่า บัฟหลบ และบัฟศรครั้งถัดไป ต้องมี state/event/ขอบเขตผลของกลไกก่อนนำสูตรภาพเข้าเกม ปัจจุบันเป็นแบบออกแบบทั้งหมด

## การส่งต่อสู่งานกลไกและภาพ

1. เก็บ ID ของ 16 สกิลปัจจุบันไว้ สกิลใหม่ 45 ID ในตารางเป็นชื่ออ้างอิงสำหรับการพัฒนาและตรวจสูตร ไม่เปิดให้เรียนผ่านการเพิ่มภาพอย่างเดียว
2. ก่อนเปิดสกิลใหม่ กำหนดดาเมจ SP คูลดาวน์ จำนวนเป้า เงื่อนไขเรียน การซ้อนสถานะและการใช้โบนัสให้ชัดเจน แยกการคำนวณเหล่านี้ออกจาก renderer และ Part definitions
3. สกิลอาคมต้นทางที่นักสู้ครุฑารับต่อใช้ ATK/MATK ตามสาย ส่วนศรสองศาสตร์ใช้ DEX เป็นแกนและ INT เสริมตามชุดสกิลที่ตกลงไว้ ทั้งสองเป็นข้อกำหนดกลไกสำหรับสกิลใหม่/สูตรที่ปรับ ไม่ใช่ผลจากการย้อมสี Part
4. บัฟซ้ำประเภทใช้ค่าที่แรงที่สุดและรีเฟรชตามกติกาที่กำหนด พิษ/เลือดไหลไม่สะสมไม่จำกัด บอสต้าน/ลดระยะควบคุมได้ เครื่องหมายล่ากับสถานะตรึงเป็นคนละข้อมูล
5. สกิลเคลื่อนที่ใช้พิกัดก่อน–หลังที่ระบบยืนยัน เคารพขอบแผนที่ สิ่งกีดขวาง และประตู Auto Quest ใช้เงื่อนไขเอาตัวรอด/รักษาระยะก่อนเลือกคอมโบ และไม่ถูก VFX เปลี่ยน destination
6. เมื่อนำชุดสกิลเข้าเกม ต้องรักษาความคืบหน้ารูปแบบปัจจุบันโดยเพิ่มระดับเริ่มต้น 0 ให้สกิลใหม่ที่ยังไม่เคยเรียน การเพิ่มช่องใหม่ไม่คืนไอเทม/สกิลที่ลบแล้วและไม่เปิดการย้ายเซฟโบราณกลับมา สถานะ VFX/transient ไม่บันทึกเป็นความคืบหน้าถาวร

## ชิ้นงานและเกณฑ์ตรวจสำหรับการผลิตถัดไป

- แผ่นตัวอย่างต้องแสดง Part แยกบนพื้นสว่าง/มืดและพื้นโปร่งใส มีขนาดใช้งานจริง ชื่อ ID และช่อง scrub เวลา เพื่อแยกภาพออกจากผลเกม
- ชุดนำร่องใช้รูปทรง Class 1 ทั้งห้าสายและ Part กลาง นำมาประกอบสกิลปัจจุบันในสี่ทิศก่อนขยายรูปทรง Class 2 ทั้งหมด
- ทุก Part สถานะมีภาพเริ่ม/คงอยู่/จบหรือถูกใช้ พร้อมกรณีหมดอายุ เป้าตาย ถูกล้าง ย้ายแผนที่ และภูมิคุ้มกันตามข้อมูลจริง
- ตรวจภาพซ้อนหลายเป้า/หลายฮิตที่ 1440 และ 390 CSS pixels ให้ใบหน้า ท่าถือ เลขดาเมจ และขอบเขตพื้นที่ยังอ่านได้ รูปพิษ เลือดไหล ขดตรึง และตราล่าแยกกันด้วยรูปทรง
- ตรวจ render ซ้ำจาก snapshot เดิมให้ได้ภาพเดิม ไม่เปลี่ยน RNG/สถานะ และไม่เพิ่มผลเกมจากจำนวนเฟรม รวมการชดเชยเวลาหลังแท็บถูกพัก
- การเปิดใช้กลไกใหม่และภาพต้องมีการตรวจเรียน/สืบทอด/บันทึกเซฟ/Auto Quest ของสกิลนั้นก่อนเผยแพร่ ไม่ถือว่าภาพตัวอย่างเป็นหลักฐานว่ากลไกใหม่เปิดแล้ว

## การตรวจเอกสารรอบนี้

ตรวจรายการแบบครั้งเดียวจากตาราง: Part ID ไม่ซ้ำ 58 รายการ (ส่วนกลาง 8, Class 1 รวม 20, Class 2 รวม 30), สูตรสกิลไม่ซ้ำ 61 รายการ, สกิลปัจจุบัน 16 ID และชื่อไทยตรงข้อมูล 1.16, สูตรเสนอเพิ่ม 45 รายการ, สกิลติดตัว 15 รายการ และ Part references ในสูตรอ้างถึงนิยามที่มีครบ ไม่มีการแก้ runtime หรือเผยแพร่เกมจากงานเอกสารนี้
